AIPG Support Desk - how to run
=======================
Requirements
------------
- Visual Studio 2022 with the "ASP.NET and web development" workload and the .NET 6 SDK/runtime
- SQL Server (Express is fine)

1. Database
-----------
Option A - use the supplied data (CSMS.bak)
   CSMS.bak was taken on SQL Server 2022 (version 16). SQL Server can only restore a backup on the
   same or a newer version, so this needs SQL Server 2022 or later.
   SSMS > Databases > Restore Database > Device > CSMS.bak > restore as "CSMS".
   Nothing else to do: the migrations are already recorded in that database.

Option B - start with an empty database (also the way to go on SQL Server 2019)
   Do nothing. On first start the application creates the "CSMS" database and all tables by itself
   and, because the database has no users yet, creates a first administrator:
        user name and password: "SeedAdmin" in appsettings.Development.json
   That password only opens one page: the first sign-in has to choose a new one (version 3.2). Because the
   file is in the repository, treat the password in it as public.
   That administrator can then create brokerage houses and branches, which registration needs.

2. Connection string
--------------------
XFLCSMS/appsettings.json > ConnectionStrings > DefaultConnection
   default:  Server=.\SQLEXPRESS;Database=CSMS;Trusted_Connection=True;...
   - "."            = this computer
   - "\SQLEXPRESS"  = instance name. For a default (unnamed) SQL Server instance use  Server=.
(The connection string is no longer hard-coded in Data/DataContext.cs.)

3. Run
------
Open XFLCSMS.sln and press F5 (profile "XFLCSMS" -> https://localhost:7044 or http://localhost:5100).
Do NOT run Add-Migration: the model and the migrations are in sync. Update-Database is not needed either
(the application applies pending migrations at start-up; set "Database": { "AutoMigrate": false } in
appsettings.json to switch that off).

4. E-mail
---------
Registration, "forgot password" and the e-mail notifications use the mail server entered in the application:
sign in as platform admin > System > Notification settings > E-mail server (password stored encrypted in the
database; "Send test e-mail" shows at once whether it works). While nothing is entered there, EmailHost /
EmailUsername / EmailPassword of appsettings.json are used (Gmail SMTP, port 587). If the mail cannot be sent
the user sees a message instead of an error page.
The system also works without e-mail:
   - a registration whose mail failed is kept as "Not verified"; the administrator activates it under
     Users (the menu shows how many accounts wait);
   - the administrator can create an account himself (Users > New user; active at once);
   - the administrator can set a new password for a user (Users > Edit).

5. Interface
------------
The pages no longer use AdminLTE, Bootstrap, jQuery or any CDN: everything is in wwwroot (css/app.css,
js/app.js, js/charts.js, fonts, img/icons.svg, img/brand-logo.png), so the application also runs on a network
without internet access. The charts are drawn by js/charts.js, without a chart library.
Colours and fonts are variables at the top of css/app.css. Pages shared by all roles are in Views/Shared.

6. Letting other people use it (brokerage houses, colleagues)
-------------------------------------------------------------
"dotnet run" / F5 answers on localhost only: nobody else can open it. For other computers:

a) Same office network
   1. Start it with the "lan" profile (plain http on port 5100, all network cards, Production mode):
          dotnet run --launch-profile lan
   2. Allow the port in Windows Firewall, once, in a terminal opened "as administrator":
          netsh advfirewall firewall add rule name="AIPG Support Desk" dir=in action=allow protocol=TCP localport=5100
   3. Find the address of this computer:   ipconfig   (IPv4 Address, for example 192.168.1.25)
   4. The others open   http://192.168.1.25:5100
   The first start on an EMPTY database must be the normal profile (F5 / plain "dotnet run"): only that one
   reads appsettings.Development.json and creates the first administrator.
   Plain http means passwords cross the network unencrypted. Fine inside one office, not beyond it.

b) Brokerage houses outside the office (the real use)
   Needs a server they can reach and https: publish the project (dotnet publish -c Release), host it in IIS
   (ASP.NET Core Hosting Bundle) or as a Windows service behind a reverse proxy, with a certificate and a
   DNS name, and set ASPNETCORE_ENVIRONMENT=Production. The application itself needs no change for this.

Before a brokerage house can start, the administrator needs: the house (Brokerage houses > New), at least
one branch for it (the list flags a house without one), and then either the staff register themselves or
the administrator creates their accounts.

7. First steps after updating to version 3.0
--------------------------------------------
Start the application once: it adds its new tables by itself (nothing existing is changed) and brings the
status of old tickets in line with the eight statuses. Then, signed in as platform admin:
   a) System > Notification settings
        - "Address of this site": check it and press Save. Until it is saved, e-mails carry no link.
        - E-mail server: enter host, user, password, sender; "Send test e-mail".
        - SMS gateway (optional): address and fields of your SMS provider, then switch SMS on.
        - The table decides which event is reported through which channel.
   b) System > Roles & permissions: what each of the five roles may do. The defaults are sensible.
   c) Users > Edit: give one person of each brokerage house the role "House admin". He then manages the
      people and branches of that house himself.
   d) System > Demo data > Load demo data: houses, people of every role and 64 tickets in every status, to
      try everything. The page shows the accounts and their password. Best on a test database: the demo
      manager and engineers are working accounts. "Remove demo data" takes it away again.

The folder XFLCSMS/App_Data/keys is created at the first start. It holds the keys for sign-in cookies and
for the stored mail password / SMS key. The account the site runs under must be able to write there. Do not
commit it and do not let a deployment delete it. After a move to another server: enter the mail password and
the SMS key again (the settings page says when that is needed).

Run ONE instance of the application: the messages that appear on open pages are passed on inside the process.

8. First steps after updating to version 3.1
--------------------------------------------
Start the application once. It adds the table "Products" and a column "ProductId" to the support lists and
the tickets (nothing existing is changed), and - once, when there is no product yet - five starting products
with their support types and categories.
   a) Administration > Products: rename the starting products to the real product names of AIPG, delete what
      does not apply, add what is missing. Only "Trading OMS" is a real name; the others are a start.
      Open a product to change its support types and categories.
      To start without the starting list, set  "Products": { "Seed": false }  in appsettings.json BEFORE the
      first start with this version.
   b) The support types and categories that existed before are kept as "All products": they are offered
      whatever the product. Edit one and choose a product to make it belong to that product only.
   c) Dashboard > Customize: every person arranges the own dashboard; nothing to set up.
The old logo file XFLCSMS/wwwroot/img/XFLlogo.png is not used any more and can be deleted.
If a page looks unstyled right after the update, reload it once with Ctrl+F5 (the browser kept the old files).

9. Version 3.2: sign-in protection, browser protection, upload limits
--------------------------------------------------------------------
Start the application once: it adds three columns to the Users table (FailedAttempts, LockedUntil,
MustChangePassword) by itself. Nothing else in the database changes, and everybody's password keeps working.

What is different for people:
   - A new password needs 10 characters with at least one letter and one digit, must not contain the user
     name or e-mail address and must not be a common one. Passwords that exist stay valid until changed.
   - Five wrong passwords (or activation tokens) in a row lock the account for 15 minutes. An administrator
     ends a lock under Users > Edit > "Unlock now"; setting a new password or a reset by e-mail ends it too.
   - Whoever signs in with a password somebody else chose (the first administrator's from the settings file,
     an account an administrator created, a password an administrator set) has to choose an own one first.
   - "Forgot your password?" answers the same for every name, so it no longer tells who is registered.
   - A file may be 10 MB, 10 files at once, and its content has to match its type.

Settings (appsettings.json; every one is optional, these are the defaults):
   "SignIn":   { "MaxFailuresPerAccount": 5, "LockMinutes": 15, "MaxFailuresPerAddress": 30, "AddressWindowMinutes": 10 }
   "Uploads":  { "MaxFileMb": 10, "MaxFilesPerSave": 10 }
   "Session":  { "IdleMinutes": 10, "CookieSecure": "auto" }       "always" = cookies only over https
   "Security": { "ContentSecurityPolicy": "enforce" }              "report" = only note violations, "off"

"MaxFailuresPerAddress" counts failed attempts from one network address. Behind a reverse proxy that does
not pass the visitor's address on, every visitor has the proxy's address: raise the number or configure
forwarded headers before going live that way.

To do by hand, once (System > System health reminds you of the first two):
   a) The mail password stands in appsettings.json, and that file is in the repository: change the password
      at the mail provider, enter the new one under System > Notification settings (it is stored encrypted
      in the database) and empty "EmailPassword" in the file.
   b) Sign in as the first administrator and choose a new password, if it is still the one from the file.
   c) Stop tracking files that do not belong in a repository (they stay on your disk):
          git rm --cached add_admin.sql
          git rm -r --cached XFLCSMS/wwwroot/Uplods
          git commit -m "Stop tracking the admin script and uploaded files"
      .gitignore now keeps them out. They remain in the history of the repository: for a public repository
      that means the uploaded files and the old password can still be read there. Rewriting the history
      (git filter-repo) removes them; changing the password is what makes the old one worthless.

10. Version 3.3: conversation, service targets, canned replies, rating, service report
------------------------------------------------------------------------------------
Start the application once: it adds two tables and some columns by itself, turns the old "Comments" text of
every ticket into the first entry of its conversation, and adds four starter canned replies.

Then, signed in as platform admin:
   a) System > Service targets: the times per priority, the working days and hours, the days off.
      The defaults are assumptions (High 0.5 h / 4 h, Medium 2 h / 18 h, Low 4 h / 45 h; Sunday to Thursday,
      09:00 to 18:00; no days off). Tickets that exist already have no targets and are never reported as late.
   b) Tickets > Canned replies: change the four starters to the wording of your team.
   c) System > Notification settings: five new events (reply, internal note, rating, target due soon, target
      missed). A reply and a missed target also go out by e-mail unless you switch that off.
   d) System > Roles & permissions: three new permissions under "Service".

Setting (appsettings.json, optional):   "Sla": { "CheckSeconds": 60 }   how often the targets are checked.

11. Version 3.4: knowledge base, tags, linked tickets, watching, automation
---------------------------------------------------------------------------
Start the application once: it adds five tables and four columns by itself. Nothing else changes: no rule
is switched on and the knowledge base is empty.

Then, when you want to use them:
   a) Tickets > Knowledge base > New article. A good start: the questions the team answered more than twice.
      A solved ticket has the button "Write an article from this ticket" (rewrite it in general words; take
      out names and numbers of the brokerage house before publishing).
   b) System > Automation: who gets a new ticket; closing after "Deployed"; reminders while "Pending".
      Everything is off until you switch it on. Start with one rule and watch the history of a few tickets.
   c) Administration > Products > Edit: a default engineer per product, if a product has "its" engineer.
   d) System > Roles & permissions: two new permissions under "Service" (write the knowledge base: every
      AIPG role; automation: platform admin and support manager).
   e) System > Notification settings: one new event, "Reminder while a ticket is pending".

Setting (appsettings.json, optional):   "Automation": { "CheckSeconds": 300, "MaxPerCheck": 20 }   how often
the rules that depend on time are applied, and on how many tickets at most per check.

The name and the logo (AIPG edition)
   The application is called "AIPG Support Desk"; the line under every page reads "Design By: AIPG Studios -
   Developed By: AIPG Systems - Powered By: AIPG". All of it is in one file: XFLCSMS/Infrastructure/Ui.cs
   (Brand, SupportTeam, Logo, DesignBy, DevelopedBy, PoweredBy and the three marks beside them).
   The logo is XFLCSMS/wwwroot/img/brand-logo.png (the AIPG mark); the credits also show the marks of AIPG
   Studios (img/aipg-studios.png) and AIPG Systems (img/aipg-systems.png). All three are square pictures on a
   clear background; the tab icon is XFLCSMS/wwwroot/favicon.ico.
   What is NOT renamed: the project folder and namespace (XFLCSMS), the repository, the database. Texts that
   are already stored in your database keep their wording (the four starter canned replies sign with "XFL
   Support", the first brokerage house is called as you named it): change them on their pages.
